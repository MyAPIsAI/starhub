# StarHub 图片生成中转接口测试报告

## 1. 测试摘要

| 项目 | 结果 |
| --- | --- |
| 测试日期 | 2026-09-23（Asia/Shanghai） |
| 被测接口 | `POST /v1/images/generations` |
| 被测模型 | `gpt-image-2` |
| 真实上游请求 | HTTP 200，成功返回 1 张有效 PNG；端到端耗时 **51,373.4 ms** |
| 项目中转开销 | 本地固定响应、15 组配对请求的差值中位数 **13.51 ms** |
| 真实请求的 StarHub 内存 | 工作集从 **15.32 MiB** 增至采样峰值 **74.62 MiB** |

**结论：** StarHub 当前承担图片请求的鉴权、路由、计费和响应转发，不在本地运行生图模型。真实请求的 51.37 秒是完整链路耗时，包含上游生成；受控本地测试估计 StarHub 为同体积图片响应增加约 13.5 毫秒。这个估计不能替代真实请求的逐段计时。

**P3 范围声明：** 本报告的性能实测只覆盖 [P3.1 图片 Relay](../require/P3.1图片Relay.md)中的同步文生图路径。第 6 节补充现有 P3 自动化回归结果；本报告不是 [P3 多协议扩展](../require/P3多协议扩展.md)所有接口的性能或真实上游验收报告。

## 2. 测试环境与口径

| 项目 | 配置 |
| --- | --- |
| 项目版本 | Git 提交 `d5766ab`，叠加测试时的未提交工作区状态 |
| 运行环境 | Windows 10.0.22631，x64；Go 1.26.0，`windows/amd64` |
| StarHub 部署 | 从当前工作区编译，使用独立临时进程和 SQLite 数据库 |
| 后台任务 | 临时实例关闭渠道定时测活及任务轮询 |
| 真实上游 | `https://www.cctq.ai`，OpenAI 兼容图片接口；报告不记录上游密钥 |
| 计时终点 | 客户端收到并完整缓冲 HTTP 响应体；不包含随后解析 JSON、解码及保存图片的耗时 |
| 内存指标 | StarHub 进程的 Windows 工作集（`WorkingSet64`），真实请求期间每 50 ms 采样一次 |

为区分上游耗时与项目耗时，本报告分别使用两个场景：

1. **真实上游场景：** 客户端 → StarHub → 上游生图服务，测可用性和完整链路耗时。
2. **固定响应场景：** 本地模拟上游始终返回同一张图片，分别直连模拟上游和经 StarHub 请求；配对耗时之差估计中转开销。

这两个场景的耗时不可直接相减来推导某一次真实请求的精确上游耗时。CCTQ 的[图片接口文档](https://doc.cctq.ai/guide/images-async.html)说明，不传 `async` 时使用同步响应；本次真实请求采用同步方式。

## 3. 真实上游生图测试

### 方法

- 在临时 StarHub 实例中配置单个 `gpt-image-2` 渠道，向 `/v1/images/generations` 发送一张 `1024x1024` 图片请求。
- 请求主题为蓝色陶瓷杯产品照片。上游密钥仅用于临时渠道配置；测试结束后临时实例和数据库已删除。
- 校验 HTTP 状态、图片数量、PNG 文件签名、图片尺寸，并人工查看生成结果。

### 结果

| 指标 | 实测值 |
| --- | ---: |
| 成功请求 | 1 / 1 |
| HTTP 状态 | 200 |
| 返回图片数 | 1 |
| 端到端响应时间 | 51,373.4 ms |
| JSON 响应体 | 2,152,239 字节（2.05 MiB） |
| 解码后的 PNG | 1,613,815 字节（1.54 MiB） |
| PNG 尺寸 | 1254 × 1254 像素 |
| StarHub 请求前工作集 | 15.32 MiB |
| StarHub 采样峰值工作集 | 74.62 MiB |
| StarHub 请求后工作集 | 74.62 MiB |
| 请求前至采样峰值增量 | 59.30 MiB |

返回体比 PNG 文件大约 33.36%，与图片在 JSON 中使用 Base64 编码的体积开销相符。内存增量是**整个 StarHub 进程工作集的变化**，包括 Go 运行时、SQLite、HTTP/JSON 处理及可能尚未归还给操作系统的内存；不能解释为单张图片固定需要 59.30 MiB。50 ms 采样也可能遗漏更短暂的峰值。上游服务的 CPU、内存和显存不在本次观测范围内。

## 4. StarHub 中转开销测试

### 方法

- 本地模拟上游预先加载上一节生成的 PNG，每次固定返回含 `b64_json` 的 JSON，响应体为 **2,151,798 字节**；与真实响应仅差 441 字节。
- 直连模拟上游与经 StarHub 的请求使用相同的请求体和同一张图片。两条路径的客户端连接均复用。
- 每条路径先预热 2 次，再执行 15 组配对请求；交替调整两条路径的先后顺序。全部请求返回 HTTP 200，且两条路径收到的响应体长度相同。
- “中转开销”按每组的 `经 StarHub 耗时 − 直连耗时` 计算，再取这些差值的中位数。

### 结果

| 路径 | 请求数 | 耗时中位数 | P95（最近秩法） |
| --- | ---: | ---: | ---: |
| 直连本地模拟上游 | 15 | 3.14 ms | 4.86 ms |
| 经 StarHub 中转 | 15 | 16.51 ms | 31.81 ms |
| 配对中转开销 | 15 组 | **13.51 ms** | **28.67 ms** |

| StarHub 内存指标 | 实测值 |
| --- | ---: |
| 预热后工作集 | 30.81 MiB |
| 进程峰值工作集 | 71.16 MiB |
| 测试结束时工作集 | 70.25 MiB |

本测试的 P95 使用最近秩法；样本量只有 15，P95 实际取第 15 个值，即该组最大值。内存数据覆盖预热和整轮重复请求，**不是单次请求的额外占用**。配对差值包含 StarHub 引入的额外本地 HTTP 跳转、鉴权、路由、计费和响应处理；它不等同于纯 CPU 执行时间。

## 5. 可用性、限制与后续测量

- **已验证：** 当前工作区代码可以编译；真实渠道同步生成返回 1 张可读取、可显示的 PNG；本地固定响应经 StarHub 的 15 次请求均成功。
- **样本限制：** 真实上游只请求 1 次，不足以代表平均值、尾延迟或故障率；本地测试为单并发、同机回环网络，不代表生产网络和多并发负载。
- **未覆盖：** 图片编辑、流式生成、重试与故障切换、并发峰值、长期内存稳定性，以及上游资源占用。
- **精确归因：** 若需得到真实请求中 StarHub 的逐段耗时，应在请求进入、上游请求发出、上游响应头到达、响应体完成等位置增加计时，再做多次实测。当前 13.51 ms 是同体积固定响应下的估计值。

测试未修改运行中的 StarHub 渠道配置；临时进程、数据库和测试程序已清理。仓库中保留了本报告及生成图片作为测试产物。
