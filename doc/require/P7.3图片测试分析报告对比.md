# P7.3 图片测试分析报告对比:P7.1 与 P7.2 的定位、方法与结论

> 状态:对比分析完成(2026-09-23)
> 结论先行:P7.1 与 P7.2 同日完成,但定位互补而非重叠——P7.1 以 mock 上游做网关内部剖析与内存拷贝优化落地,深度优先;P7.2 以真实上游做端到端可用性验证与中转开销估算,广度优先。两者均确认「网关开销毫秒级、真实链路由上游主导、P3.1 图片 Relay 生产可用」,共同支撑该结论。

## 二、测试方法对比

| 项 | P7.1 | P7.2 |
| --- | --- | --- |
| 真实上游 | 否(隔离测网关自身开销) | 是,1 次同步生成 1024×1024 |
| 配对中转开销 | 否 | 15 组配对(直连模拟上游 vs 经 StarHub) |
| 迭代规模 | 40 次性能场景 + 30 次内存 + 24 并发 × 3 | 真实 1 次 + 固定响应 15 组配对 |
| 内存口径 | Go `runtime.MemStats`(HeapAlloc / TotalAlloc / GC 次数) | Windows `WorkingSet64`(整个进程工作集,50 ms 采样) |
| 计时终点 | 客户端完整收到响应体 | 同;但**不**含 JSON 解码与图片保存 |
| 统计指标 | p50 / p95 / p99 / max | 中位数 + 最近秩法 P95(样本仅 15,P95 实取最大值) |
| 被测模型 | `gpt-image-1`(mock) | `gpt-image-2`(真实) |
| 被测服务 | `httptest` 内嵌完整路由(含中间件链) | 独立临时进程 + 临时 SQLite,关闭后台测活/轮询 |

## 三、核心数据对比

| 指标 | P7.1 | P7.2 |
| --- | --- | --- |
| 端到端耗时 | mock 即时;500 ms 上游时 p50=532.6 ms | 真实 **51,373.4 ms**(主因上游推理) |
| 网关开销 | 5~10 ms/MB;1024² 非流式 p50 13.6 ms | 配对中转开销中位数 **13.51 ms**,P95 28.67 ms |
| 并发吞吐 | 86.2 req/s(72/72 成功 ≈ 92 MB/s) | 单并发,未测 |
| 内存(关键) | HeapAlloc 1.4→1.4 MB 无泄漏,峰值 8.2 MB | 工作集 15.32→74.62 MiB(整进程,含未归还 OS 的内存) |
| 计费正确性 | 4 图 × $0.001 精确扣费,实测验证 | 依赖 P3 自动化测试覆盖,未在本报告单独实测 |
| 真实图片产物 | 无(mock) | 1 张可读 PNG,1254×1254,1.54 MiB |

> **口径警示**:两份内存数值**不可直接对比**。P7.1 是 Go 堆指标(HeapAlloc),P7.2 是 OS 工作集(WorkingSet64,含 Go runtime、SQLite、HTTP 管道及尚未归还 OS 的内存)。P7.2 第 3 节亦明确说明「不能解释为单张图片固定需要 59.30 MiB」。

## 四、互补关系

### P7.1 的强项

- 多场景延迟分位数(p50/p95/p99/max,40 次迭代)
- 并发吞吐量化(24 并发 × 3,72 请求)
- GC 行为与每请求分配量剖析
- 内存拷贝**逐段量化**(ReadAll / ParseImageResponse / ParseImageStreamEvent / SSEReader),给出 2~3 份 holding 的根因
- 优化方案(三路径收敛到 ≤1 份)+ 第三部分**已落地记录** + A/B 实测对比

### P7.2 的强项

- 真实上游首次端到端验证(返回有效 PNG,校验文件签名/尺寸)
- 配对法估算中转开销(15 组配对,交替顺序消除先后偏差)
- 明确的样本限制与后续测量建议(第 5 节)
- P3 全量 21 项回归对照(第 6 节),含 `TestP3Image*` 6 项
- 真实链路内存采样(50 ms 粒度)

### 各自的边界

- **P7.1 弱点**:mock 上游无法反映真实推理耗时与尾延迟;性能数据是「纯网关开销」上界估计。
- **P7.2 弱点**:真实请求仅 1 次,不足以代表平均值、尾延迟或故障率;无并发/流式/编辑路径的真实数据;未做内存拷贝剖析;P95 在 n=15 下实取最大值,统计意义有限。
- **覆盖缺口**(两者均未覆盖):图片编辑真实上游、流式生成真实首图时间、重试与故障切换、并发峰值、长期内存稳定性、上游资源占用。

## 五、一致结论

两份报告在以下结论上相互印证:

1. **功能可用**:`/v1/images/generations` JSON 与 SSE 两路径、单图与多图、计费闭环均正确。
2. **网关开销毫秒级**:P7.1 测得 5~10 ms/MB;P7.2 配对法测得中位数 13.51 ms——量级一致。
3. **真实链路由上游主导**:P7.2 实测 51.37 s 端到端,P7.1 在 500 ms 上游下网关增量仅 32.6 ms,占比 <1%。
4. **P3.1 图片 Relay 生产可用**:P7.1 给出优化落地证据,P7.2 给出真实链路可用性证据。
