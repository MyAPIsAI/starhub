# P4 用户与运营体系：让中转「能商用」

## 4.1 账户与权限

- 注册/登录（邮箱验证、密码策略）、OAuth（GitHub/Discord/OIDC）
- 角色分层：`普通用户 → 管理员 → Root`（`common.Role*`），管理端细粒度权限用 Casbin（`service/authz`）
- 敏感操作审计（`middleware/audit.go`：管理员写操作自动留痕）

## 4.2 令牌治理（P0 的 Token 表扩展）

| 能力 | 字段 | 价值 |
|---|---|---|
| 模型白名单 | `ModelLimits` | 子 key 只准用便宜模型 |
| IP 白名单 | `AllowIps` | 企业客户防泄露 |
| 有效期/额度 | `ExpiredTime` / `RemainQuota` | 预付费卡密模式 |
| 指定分组 | `Group` | 同一用户多业务隔离（受 `UserUsableGroups` 约束） |
| auto 分组 | `AutoGroups` | 一次请求按序尝试多组渠道 |

## 4.3 分组体系完整版

从 P0 的"单 default 组"扩展为定价+路由双维度：

- `group_ratio`：分组计费倍率（VIP 组 0.8 = 八折）
- `group_group_ratio`：用户组 × 使用组 的二维倍率矩阵
- `auto` 组：按 token 配置的组序列依次尝试，实现"优先便宜渠道，失败降级贵渠道"

## 4.4 商业化配套

充值支付（易支付/Stripe/Creem）、邀请返利（AffCode）、兑换码、订阅；限流体系四级：全局 → 用户 → 令牌 → 模型（`middleware/rate-limit.go` + `model-rate-limit.go`）。
