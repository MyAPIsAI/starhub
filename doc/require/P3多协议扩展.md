# P3 多协议扩展：让中转「广接入」

## 3.1 适配器架构（已验证的抽象）

统一接口 `relay/channel/adapter.go:16`，每个供应商一个包：

```
新增渠道只需实现:
Init / GetRequestURL / SetupRequestHeader
ConvertOpenAIRequest（协议转换核心）
DoRequest / DoResponse
GetModelList / GetChannelName
```

注册进 `relay/relay_adaptor.go:56` 的 switch。

**先用 3 个高价值渠道验证抽象：Claude（鉴权头不同）、Gemini（路径风格不同）、AWS（签名 V4）**——覆盖了三种典型差异，后续 40+ 渠道都是模式复用。

## 3.2 格式互转矩阵

入站协议 × 出站协议自由组合：

- `/v1/messages`（Claude 格式）请求 → 路由到 OpenAI 渠道：`ClaudeHelper` 内做 DTO 互转
- `chatCompletionsViaResponses` / `responses_via_chat`：模型只支持其中一种 API 时自动桥接
- P0 只做了 OpenAI-in/OpenAI-out；P3 目标是**任意 in × 任意 out**（`dto` 层做统一中间表示）

## 3.3 任务型 API（异步任务）

视频生成（Sora/Kling）、音乐（Suno）等是"提交-轮询"模型，`TaskAdaptor`（adapter.go:35）定义了完整生命周期：

```
ValidateRequestAndSetAction → EstimateBilling(预扣) → 提交 → 轮询 ParseTaskResult
→ AdjustBillingOnComplete(终态差额结算)
```

计费钩子内建于接口，避免每个任务平台各写一套扣费逻辑。
