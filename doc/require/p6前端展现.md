# P6 前端展现：StarHub 控制台

> 状态：已实现控制台、后端前置修复、嵌入构建与验证流程；交付文件见文末。
> 核对日期：2026-09-22；后端基线：`5e4c38b`，包含 P5 可观测性及 `025c6fb` 计费修复。
> 方案：Vue 3 + TypeScript + Vite + Tailwind CSS 4 + shadcn-vue；使用现有管理 API，补齐必要的接口缺口；发行版通过 Go embed 交付单二进制。
> 本文约定 P6 为控制台，部署与多实例能力归 P7。P7 文件内仍有旧 P6 编号，后续整理时统一。

## 一、分析结论与范围

原方案的技术方向可以保留，但实施顺序应调整为：**先确认接口与权限，再完成业务闭环，最后完善图表与交付**。“简洁美观”需要具体的页面、数据口径和交互标准，不能只由组件库决定。

### 1.1 实施前基线分析（以下“当前”指基线提交）

| 原假设 | 当前代码事实 | P6 处理 |
| --- | --- | --- |
| 接入前端不需要后端改动 | 空值更新、Cookie、权限接线、审计归属和静态托管仍有缺口 | 明确 M0 后端前置项，不能仅用前端隐藏功能解决 |
| 所有列表统一分页 | 用户、渠道、令牌、兑换码返回全量数组；流水与审计才分页 | 两类列表分别适配，不能对一页数据伪造全量搜索 |
| `/api/metrics` 可直接画历史趋势 | 它是进程内累计计数和渠道最近 100 次尝试的滚动快照 | 展示当前指标及渠道对比；日趋势来自 `/api/user/usage` |
| HttpOnly Cookie 可天然防止 XSS | 只能限制脚本直接读取 Cookie；登录响应还包含 session，且脚本仍可发起请求 | 不存 session，补同源写请求保护与生产 Cookie 配置 |
| RBAC 已按策略模块执行 | `service/authz` 有策略，但当前 `main.go` / `middleware/auth.go` 没有调用它 | 区分当前权限与目标权限，M0 接入并做直接请求测试 |
| 管理员的令牌页只是“我的令牌” | 管理员列表包含所有用户令牌，创建仍属于当前登录用户 | 管理员提供“全部 / 我的”视图，并展示所属用户 |
| 消耗金额就是完整计价金额 | 修复后 `quota` 是实扣，`unfunded_quota` 是未收费用 | 单独呈现，未收费用不显示为已收入或用户欠款 |
| 运行时变量可关闭 embed、缩小包体 | embed 在编译时执行；缺少匹配文件会构建失败 | 使用构建标签区分纯后端与带前端发行版 |
| “9 个页面”即可覆盖所有管理能力 | 页面数、登录注册与个人页范围未统一，多个功能没有 API | 固定 9 个业务页面，登录/注册独立计数；不承诺缺失能力 |

### 1.2 用户目标与交付范围

普通用户应能完成：注册登录 → 兑换额度 → 创建令牌 → 复制接入信息 → 查询用量和消费流水。

运营人员应能完成：创建渠道 → 配置模型与分组 → 测试渠道 → 配置计价 → 查看运行指标与未收费用 → 管理兑换码与查询审计。

P6 包含 9 个业务页面：概览、令牌、消费流水、个人信息、渠道、用户、系统设置、兑换码、审计；另外包含登录、注册和 403/404 页面。实时指标放在管理员概览中，不再单独增加监控产品。

P6 不包含聊天 Playground、订阅/在线支付、OAuth、角色编辑、自助修改资料/密码、任务管理、跨实例指标汇总、历史 TTFT 查询、服务端导出和全局业务搜索。这些能力需要独立需求及接口，不能放置无效按钮。页头只提供导航、主题、语言和用户菜单。

### 1.3 借鉴 Talen 的边界

已对照本机 `D:/Workspace/new-api/web` 的 `package.json`、`src/styles/theme.css`、`src/hooks/use-table-url-state.ts` 及加载/空态/错误组件。借鉴领域分目录、设计令牌、状态反馈和 URL 状态同步，自行实现 Vue 版本。

不复制其 React 组件和业务代码，不沿用“所有域只能通过 api.ts 互相访问”的过度约束：`api.ts` 负责网络访问，必要的公共类型和组件通过域的 `index.ts` 显式导出；禁止跨域导入私有实现。也不把尚未核实的测试工具、图表实现和目录数量作为选型依据。

## 三、已核实的管理 API 契约

证据入口：[路由](../../main.go)、[响应格式](../../common/response.go)、[控制器](../../controller)、[数据模型](../../model)。本表描述 P6 实现后的接口契约。

### 3.1 响应与错误

管理接口正常响应是 `{success, message?, data?}`，成功写入通常返回 `{success:true}`，不能强制要求 `data` 存在。客户端同时检查 HTTP 状态及 `success`，保留状态码和后端 message；兼容空响应、非 JSON 错误和代理错误页。

中继接口不使用此管理封套；控制台首版不直接调用 `/v1`，不把用户 API Key 当作管理 session。

```ts
interface ApiResponse<T> {
  success: boolean
  message?: string
  data?: T
}

interface PageResult<T> {
  items: T[]
  total: number
}
```

数组响应和分页响应可能含 `null` 列表，适配层统一为 `[]`。不支持的字段保持缺失语义，不能统一转成 0、空字符串或 false。

### 3.2 路由、权限和数据范围

| 方法与路径 | 当前鉴权 / 数据范围 | 数据与限制 |
| --- | --- | --- |
| `POST /api/user/register` | 公开 | `username,password,email?,aff_code?`；返回用户，**不自动登录** |
| `POST /api/user/login` | 公开 | 返回 `{session,user}` 并设置 Cookie；前端只保留 user |
| `POST /api/user/logout` | 已登录 | 删除服务端 session 并使 Cookie 过期 |
| `GET /api/user/self` | 本人 | 用户公开字段及 `request_count` |
| `GET /api/user/usage` | 默认本人；管理员可指定 `user_id` | `days=1..90`，默认 7；管理员 `user_id=0` 表示全站；返回 `{days,items}` |
| `GET /api/user` | 当前 admin/root | 全量用户数组，无服务端分页/搜索 |
| `PUT /api/user` | 仅 root | body 含 `id`，可改 quota/status/group/password；改 quota 必须附读取时的 expected_quota，冲突返回 409；不能改 role/username/email |
| `GET /api/channel`、`GET /api/channel/{id}` | admin/root | 全量数组 / 单条详情，密钥均掩码 |
| `POST /api/channel`、`PUT /api/channel`、`DELETE /api/channel/{id}` | admin/root | 更新 ID 放 body；创建和更新返回掩码后的渠道 |
| `POST /api/channel/test/{id}?model=...` | admin/root | 返回 `{ok,model,elapsed_ms,message,status}`；外层成功不代表探测成功 |
| `GET /api/token` | 普通用户本人；admin/root 全部 | 全量数组，key 掩码 |
| `POST /api/token` | 当前登录用户 | 新 token 始终归本人；成功响应含完整 key |
| `PUT /api/token`、`DELETE /api/token/{id}` | 本人或 admin/root | 更新 ID 放 body；当前无 token status 更新和密钥重置接口 |
| `GET /api/option`、`PUT /api/option` | admin/root | 列表为 `[{key,value}]`；value 是字符串；每次 PUT 只改一个 key |
| `GET /api/log` | 普通用户本人；admin/root 全站 | `p,page_size,model`；model 为精确匹配；返回 `{items,total,page,page_size}` |
| `GET /api/audit` | admin/root | `p,page_size`；返回 `{items,total}`；无搜索/详情接口 |
| `GET /api/metrics` | admin/root | `{requests,channel_stats,window,generated_at}` |
| `GET /api/redemption`、`POST /api/redemption`、`DELETE /api/redemption/{id}` | admin/root | 列表全量；创建返回 `{codes,count}`，支持 1..100 个 |
| `POST /api/user/redeem` | 本人 | `{code}`；返回 `{quota,message}`，quota 是本次入账量，不是最新余额 |

`/v1/models` 需要 API Key，不能用管理 Cookie 代替。当前没有面向普通用户的模型/分组发现接口，也没有公开的“注册是否开启”接口；不要擅自依赖它们。

### 3.3 列表适配和 URL 状态

- 用户、渠道、令牌、兑换码：P6 首版对已完整加载的数组做本地筛选、排序和分页；明确显示“共 N 条”。本地操作不能降低接口传输量，不视为大数据方案。
- 消费流水：使用服务端分页，显式发送 `p>=1` 和 `1<=page_size<=100`，默认 20。controller 查询与回显均使用规范化参数；前端仍规范化 URL 参数。
- 审计：同样显式发送分页参数；当前响应不含页码，以请求参数维持页面状态。
- 流水只开放后端支持的 model 筛选；审计不展示不存在的全局筛选。若增加用户、渠道、状态或日期筛选，必须同步增加服务端查询与测试。
- URL 保存页码、页大小及受支持的非敏感筛选。筛选变化回第 1 页；浏览器前进/后退还原状态；删除最后一条后回到仍有数据的页。
- 不把当前页本地排序伪装成跨页排序；P6 的流水与审计按后端默认倒序展示。
- 不把密钥、session、密码、兑换码和 webhook URL 写入 URL。无需保存搜索词时不保存。
- 超出全量列表的性能验收规模后，安排服务端分页升级；不通过前端截断数组假装数据完整。

## 四、页面与交互规格

### 4.1 导航与目标权限

| 页面 / 路由 | user | admin | root |
| --- | --- | --- | --- |
| 概览 `/console/overview` | 个人用量 | 个人用量 + 全站用量 + 运行指标 | 同 admin |
| 令牌 `/console/tokens` | 管理本人 | 管理全部，可筛选本人 | 同 admin |
| 流水 `/console/logs` | 本人 | 全站 | 全站 |
| 个人信息 `/console/profile` | 查看资料、邀请码、自助兑换 | 同 user | 同 user |
| 渠道 `/console/channels` | 不可见 | 管理 | 管理 |
| 用户 `/console/users` | 不可见 | 只读 | 修改余额、分组、状态、重置密码 |
| 设置 `/console/options` | 不可见 | 管理 | 管理 |
| 兑换码 `/console/redemptions` | 不可见 | 管理 | 管理 |
| 审计 `/console/audit` | 不可见 | 只读 | 只读 |

用户修改通过 `middleware.AdminAuth` 接入 `service/authz` 的 root 写入策略；admin 直接 PUT 同样返回 403。暂不提供任何角色升降级入口。

会话初始化完成后才渲染受保护页面；匿名进入登录页，已登录但无权限进入 403。菜单可见性、按钮能力和路由守卫共用一份 capability 映射，但后端鉴权始终是最终约束。

### 4.2 登录、注册与个人信息

- 登录支持 Enter 提交、字段校验、提交中防重复；错误凭据显示在表单内，不触发全局 401 跳转循环。
- 注册校验按当前后端：用户名 3..64 个 ASCII 字母/数字/`_`/`-`/`.`，密码 6..64 字节；邮箱和邀请码可选。不要将 JavaScript 字符数误当作 Go 的字节长度。
- 注册成功转登录页并填入用户名；不假设获得了 session。注册默认额度为 0，登录后的零余额页引导兑换或联系管理员。
- 个人页只读展示用户名、邮箱、角色、分组、余额、累计实扣、创建时间及邀请码。邀请码可复制为同源注册链接；无邀请码时不编造。
- 自助兑换成功后重新获取 self 和相关用量数据，明确显示“本次到账”；提交超时先刷新余额，不自动再次兑换。
- 不显示无法实现的“修改邮箱”“修改密码”“找回密码”“修改角色”按钮。后续需要时先提供独立自助接口。

### 4.3 令牌

列表包含名称、所属用户（管理员）、掩码 key、余额/无限额、累计实扣、有效期、分组和只读状态；模型/IP 限制放详情或可展开区域。

创建表单支持 name、remain_quota、unlimited_quota、expired_time、group、model_limits、allow_ips、auto_groups。高级限制折叠展示；逗号分隔字段可用标签输入，但网络层保持后端字符串契约。

- “无限额”只取消 token 自身额度上限，仍受用户余额约束。
- 分组留空表示继承用户分组；`auto` 必须提供有序 auto_groups。当前没有普通用户可读的分组目录：基础入口使用继承，高级入口允许手工填写，后端校验名称；不以管理员选项接口供普通用户加载下拉菜单。
- 过期时间以 Unix 秒传输，`-1` 表示永不过期；不能把毫秒直接发送。
- 创建成功仅在一次性弹窗显示完整 key，直接复制返回值，**不再额外拼接 sk-**。关窗/离页清除组件内存，并移除包含 key 的 mutation 结果；不持久化到 Pinia、Query 缓存、日志或 localStorage。
- 网络失败且不知道创建是否成功时，先刷新列表；已有掩码 key 无法恢复全文，提示用户删除未知 token 后重新创建，不能后台自动重试 POST。
- 编辑只提交变更字段；取消表单不写接口。不支持的启停/重置按钮不展示。
- 更新接口支持空字符串清除 group/model_limits/allow_ips/auto_groups，省略字段不修改，创建时 remain_quota=0 保留。设置余额必须提交 expected_quota，包含开启不限额时将令牌余额置零的操作。
- token 配额是密钥的使用上限，修改它不是账户充值。没有固定“初始总额”字段，不绘制容易误导的余额百分比条。

### 4.4 渠道

列表展示名称、类型、模型、分组、状态、优先级、权重、测活耗时与累计实扣。支持本地筛选和创建/编辑/删除；不提供未实现的批量导入或全部测活。

表单类型固定使用已支持的 1=OpenAI 兼容、14=Claude、15=Bedrock、25=Gemini。模型非空；分组支持多个逗号分隔值；多 key 按行输入，key_mode 使用 `random` / `round_robin`。

- Bedrock key 格式提示为 `accessKeyId|secretAccessKey|region`；密钥输入默认隐藏。
- 编辑时类型只读，因为当前 UpdateChannel 不更新 Type；改变协议应新建渠道。
- 不把返回的掩码 key 填回可提交字段；未输入新密钥时完全省略 key。新密钥会重置原多 key 禁用状态，应在保存前说明。
- 状态 1/2/3 分别是启用/手动禁用/自动禁用；只有 1、2 可手工设置，不能把 3 当作普通表单选项。
- 测试先选渠道已有模型，行内显示加载、结果和 elapsed_ms；判断 `data.ok`，不是只判断 HTTP 200 或外层 success。
- 探测会实际请求上游并可能改变渠道状态；不自动重试、不随页面刷新触发。完成后刷新渠道列表和指标。
- `response_time` 是测活耗时，不标为 TTFT。密钥数量与各 key 状态只读呈现，未提供的单 key 控制不伪造。
- 编辑清空 base_url 会提交空字符串，恢复提供商默认地址；省略时保留原值。

### 4.5 用户、兑换码与审计

**用户管理**：列表展示身份、分组、状态、余额、累计实扣与创建时间；root 编辑时明确“设置当前余额”，不是“增加额度”。显示原值、新值和差额，保存前确认；通过 expected_quota 条件更新避免覆盖并发消费，冲突时刷新并重新确认。

**兑换码管理**：创建支持额度、数量 1..100、过期时间、自定义单码；数量大于 1 时禁用自定义码输入，避免后端静默忽略。列表显示未使用/已使用/已过期及 used_by/used_at，`expired_at=0` 表示永久有效。兑换码与 token 不同，管理员列表当前会返回完整 code，可显隐和复制，不宣称“只显示一次”。批量创建当前没有整批事务，失败后刷新列表核实已生成部分，不自动重放整个批次。

**审计**：展示时间、操作者 ID/名称、方法、路径、HTTP 结果、IP；没有前后值和业务详情字段，不构造不存在的差异记录。Audit 在执行管理操作前解析已认证会话并保存操作者 ID/username，包括后续被权限拒绝的写入；历史缺失身份仍显示“未记录”。

### 4.6 系统设置

按“计价 / 分组 / 推广 / 告警”分类，**每个选项独立保存**。没有跨选项事务，不提供暗示原子成功的“全部保存”。

| 选项 | 编辑形态与校验 |
| --- | --- |
| `model_ratio`、`completion_ratio`、`group_ratio` | JSON 对象，名称非空，有限数值 0..1e9 |
| `group_group_ratio` | 二维 JSON 对象，数值约束与后端一致 |
| `model_price` | 模型 → USD/次，0..10000 |
| `model_price_expr` | 模型 → 表达式字符串；前端检查 JSON/类型，语法以 Go 引擎为准 |
| `cache_ratio`、`audio_ratio` | 有限数值 0..1000 |
| `aff_rebate_ratio` | 0..1，以百分比辅助显示 |
| `aff_register_bonus` | 非负整数 quota |
| `alert_error_rate` | 0..1，以百分比辅助显示 |
| `alert_webhook_url` | URL/空字符串，按字符串选项序列化；默认隐藏敏感部分 |

传输示例：`{ "key": "model_ratio", "value": "{\"gpt-4o\":2.5}" }`。value 必须是序列化后的字符串，不能直接传对象。

展示当前值与草稿差异、未保存标记、离页确认和后端校验错误。保存成功重新 GET；失败保留草稿。前端只本地检查表达式文本，不使用 JavaScript `eval`。

计价说明必须展示优先级：表达式 > 按次 > token 倍率。按次价只有正值才启用，0 不是“免费开关”。模型与补全倍率会合并内置默认值：删除内置模型条目会恢复默认，不能表示禁止/免费；其他映射不应被误认为有同样合并行为。也不能把零倍率笼统解释成免费，需遵循后端最小计费和分组回退语义。

`billing_ratio_fallback` 与 `quota_shortfall` 当前是服务端日志标记，不存在告警历史查询 API。P6 通过消费日志字段展示未收费用，不虚构“倍率缺失告警列表”。

## 五、金额、时间与图表口径

### 5.1 金额与整数

- 统一 `1 USD = 500000 quota`；编辑提交整数 quota，展示可切换 quota / USD。
- 金额输入保留字符串，在转换时做精确十进制运算；禁止直接 `parseFloat(value) * 500000` 后截断。若允许 USD 输入，必须能精确换算为整数 quota，否则给出字段错误。
- 1 quota = 0.000002 USD；小额流水最多展示 6 位小数或同时显示原始 quota，不能统一两位小数将真实扣费显示为 0。
- 当前 API 返回 JSON 数字。读取/编辑 ID、quota、计数须验证安全整数；超过 `Number.MAX_SAFE_INTEGER` 的值不能继续参与计算或保存，显示明确的精度错误。若实际需要支持完整 int64，应先增加字符串数值 DTO 或无损 JSON 适配，不能事后用 BigInt 修复已被 JSON.parse 舍入的数字。
- 表格的“实扣费用”取 quota，“未收费用”取 unfunded_quota，“计价费用”才是二者之和。历史行默认 unfunded_quota=0 只表示没有记录差额，不能证明旧数据已足额收款。
- 用户与限额 token 的 used_quota 是累计实扣；无限额 token 当前不推进该计数，显示为“不适用”，不要拿它推算实际使用量。
- 用户余额、token 余额是当前可用额度，可能已包含在途预扣影响；不要求它们与已完成流水在请求执行期间实时恒等。
- 余额变更、兑换、令牌额度设置分别使用准确名称；不把“额度上限”“账户资金”“实扣费用”混成一个余额指标。

### 5.2 时间与日趋势

Unix 时间戳统一按秒解析为 Date。明细显示浏览器本地时间并提供时区提示；永不过期哨兵不当作 1970 年日期。

`/api/user/usage` 按 **UTC 自然日**聚合，默认最近 7 天、最多 90 天。趋势横轴保留该 UTC 日期，不把 `YYYY-MM-DD` 随意转换成本地日期。成功返回后可补齐查询区间内没有流水的日期为零；请求失败不能补零伪装为无消费。

个人视图不传 user_id；管理员的“全站”明确传 `user_id=0`。从 self 得到的 request_count 是消费日志条数，不等同于所有尝试/失败请求数，标签使用“已记账请求”。

### 5.3 管理员运行指标

依据 [metric/metric.go](../../metric/metric.go)：

- requests 是进程内累计分类计数，重启清零；channel_stats 是各渠道最近最多 window=100 次**上游尝试**，不是最近 100 秒，也不是最近 100 个最终请求。
- 渠道成功率与请求成功率分开命名。前者直接用 success_rate × 100%；若展示后者，口径为 success / 所有返回分类计数之和，零分母显示“暂无数据”。
- TTFT 单位毫秒；非流式或未取得首 token 时可能回退到响应头时间。当前聚合不能区分测量类型，提示该口径，不写成“纯流式首字时间”。
- P6 展示平均/P95 延迟及渠道横向对比，不画没有历史数据的 24 小时 TTFT 趋势，不将它外推为全站持久化 SLO。
- 当前环形窗口填满后 `last_ttft_ms` / `last_attempt_at` 的取样索引还需后端核对，首版不展示这两个“最近”字段；不影响展示已核实的窗口聚合值。
- 请求分类、窗口大小、generated_at 和“进程内指标，重启重置”说明应在界面可见。channel_stats 为空/null 时显示无样本，不能当成 0% 成功率。
- 仅在有权限且页面可见时每 30 秒轮询一次，离页停止；失败保留旧值并标记过期/更新时间，提供手动重试，不刷满 toast。
- 渠道统计按 channel_id 与渠道列表关联；关联失败显示 ID，不隐藏该条数据；明确排序，避免 sync.Map 遍历顺序导致图表跳动。

## 六、客户端状态、会话与反馈

### 6.1 HTTP 与缓存

统一管理客户端使用同源 Cookie，开发时经 Vite 代理，`credentials: 'same-origin'`；不把 session 或 API Key 放入 localStorage/sessionStorage。浏览器无需主动设置 Bearer session。

- 普通查询默认超时 15 秒；渠道探测单独给出更长超时并与后端探测上限匹配。传递 AbortSignal，取消查询不显示错误提示。
- 查询只对网络错误/部分 5xx 有限重试一次，400/401/403/404 不重试；429 按 Retry-After 或退避提示，不立即循环重试。
- 创建/删除/修改/兑换/探测均不自动重试，也不启用断网后自动补发；不做资金或权限字段的乐观更新。
- query key 包含登录用户 ID、数据范围和查询参数；退出或会话失效先取消请求，再清空业务 query/mutation 缓存、敏感表单和 auth。对晚到响应校验当前会话代次，避免把前一账号的数据重新写入。
- self 是身份数据源，Pinia 仅保存供守卫使用的受控摘要；更新 self 后同步摘要，不同时维护两个独立真相来源。
- 页面 query 只在会话就绪且能力允许时启用。管理员退出后再次由普通用户登录，缓存中不能出现全站数据。
- 令牌变更刷新 token；兑换/用户余额变更刷新相关用户与用量；渠道变更刷新渠道与 metrics；设置变更重新获取选项。只失效相关域。

TanStack Query 默认会把缓存视为 stale，并在一些生命周期事件重取；M1 显式设置 staleTime、focus refetch、重试和轮询，不能依赖默认值碰巧符合控制台需求。[Query 官方说明](https://tanstack.com/query/latest/docs/framework/vue/guides/important-defaults)

### 6.2 会话边界

服务端 session 存于内存，最长 7 天，服务重启后即失效。前端不能用 Cookie 是否存在或本地 user 缓存判断仍登录。

- 应用启动调用 self：401 转登录；网络/5xx 显示“无法验证会话”和重试，不能误判为账号退出。
- 已登录请求遇到 401，统一清理并只跳转一次；登录表单自己的 401 留在表单内。403 显示权限不足，不强制退出。
- redirect 只接受站内已知路径，不接受协议 URL 或 `//host`。
- logout 成功或确认 session 已失效后清缓存；网络失败不宣称已完成服务端注销，提供重试。多标签页广播注销事件，不广播凭据。
- Cookie 的 HttpOnly 不等于整个应用防 XSS；按文本渲染上游错误、模型名、用户名与选项，禁止未经处理的 `v-html`。
- M0 补安全 Cookie、清理 Cookie、敏感响应 no-store 与 Cookie 写请求的同源/CSRF 防护；生产 TLS 终止和可信代理配置须明确，不能盲信任所有 X-Forwarded-*。

### 6.3 通用反馈

初次加载使用骨架；已有数据刷新保留内容和轻量加载提示。骨架延迟短暂显示以免闪烁，不为每个成功请求强制增加 250ms 等待。

空列表与筛选无结果分别显示；只有用户拥有创建权限时才展示 CTA。表单错误靠近字段，整页失败提供行内重试，成功操作使用一次 toast。提交期间禁用当前操作，敏感删除使用带对象名称的确认框；失败保留输入。

## 七、视觉与可访问性验收

- 整体为中性背景、清晰主操作和有限语义色；颜色、间距、圆角、阴影、图表色均集中到设计令牌。提供浅色/深色/跟随系统及中英文，持久化的仅是 UI 偏好。
- 桌面侧栏约 240px、可折叠；页头与内容留白一致，正文最小 14px。表格默认 compact，提供 comfortable；金额与 token 数字等宽、右对齐。
- 每页优先一个主操作；概览允许多张指标卡和趋势区，不强行限制为“一张卡片”，也不堆叠多层装饰面板。
- 360px 手机布局使用抽屉导航；令牌、兑换码等可转卡片，宽流水/审计采用列优先级和表格内横向滚动，保留全部字段入口。页面本身不横向溢出，避免固定列遮挡操作。
- 在 360×800、768×1024、1440×900 及浏览器 200% 缩放下验证登录、主列表、表单与弹窗。长中文、长模型名和大数值不能挤掉关键操作。
- 键盘可完成登录、筛选、提交、关闭弹窗；焦点可见，弹窗有焦点约束并在关闭后返回触发按钮。图标按钮有可读名称，字段关联 label/error。
- 状态同时有文字/图标，不只用颜色区分；普通文本对比度以 4.5:1 为目标。图表有同源数据摘要/表格，支持减少动效偏好。
- 字体与静态资源随站点交付，不依赖外部 CDN 才能打开控制台。图表随主题变化并随容器尺寸 resize。
- 性能目标是验收预算而非现状承诺：登录首次加载不包含 ECharts，首屏 JS gzip 目标不超过 300 KiB；超出需记录原因及拆包措施。全量列表以 1,000 条模拟数据验证交互，不将其视为无上限支持。

## 九、开发与单二进制交付

### 9.1 开发环境

前端在 `web/` 启动 Vite，`/api` 代理到本机 Go 的 `:3000`，浏览器通过前端 origin 请求。控制台没有中继调用需求，首版不增加 `/v1` 代理和 API Key 输入。

明确支持部署在站点根路径；任意子目录部署不在 P6 范围。正式界面业务路径为 `/console/*`，登录与注册分别为 `/login`、`/register`，站点根路径跳到概览。

### 9.2 构建模式

纯后端默认构建保留原命令，不要求 Node 或 `web/dist` 存在：

```sh
go build ./...
go vet ./...
go test ./...
```

带控制台的发行版先在 `web/` 执行：

```sh
npm ci
npm run lint
npm run typecheck
npm run test:unit
npm run build
```

再在仓库根目录执行：

```sh
go test -tags frontend ./...
go build -tags frontend -o starhub .
```

上述 npm scripts 和构建标签已落地。浏览器测试单独执行 `npm run test:e2e`，自动启动隔离的 Go 测试实例与 mock 上游，不使用生产数据库/真实上游密钥。

`web/assets_embed.go` 使用 `//go:build frontend` 和 `//go:embed dist`；`assets_stub.go` 使用 `!frontend` 提供同名空实现。发行构建缺少 dist 时应明确失败，不能嵌入占位页假装成功；默认 Go 构建走 stub。

embed 模式相对于所在 Go 包匹配文件，需从 `fs.Sub(assets, "dist")` 获取站点根。不通过运行时 `STARHUB_NO_EMBED` 解决编译期匹配错误；它也不能减少已经嵌入的二进制体积。[Go embed 文档](https://pkg.go.dev/embed)

### 9.3 静态路由边界

在管理/中继路由外建立明确的分发层：`/api`、`/api/*`、`/v1`、`/v1/*` 始终交给原 API mux，**包括未知路径和错误方法**。只给剩余浏览器页面请求使用静态 handler。

不能仅加一个无约束的 `mux.Handle("/", spaHandler)` 并假设 API 不受影响：兜底路由可能把未知 API 或错误方法变成 HTML。

静态 handler 应满足：

- GET/HEAD 的已存在资源按正确 MIME 返回；只对 `/login`、`/register`、`/console/*` 等前端路径回退 index.html，前端未知业务子路由显示 404 页面。
- 缺失的 `/assets/*`、脚本、图片等返回 404，不回退 HTML；非 GET/HEAD 的非 API 请求返回 405。
- API 的 404/405/401/403 保持原有状态及响应处理，不变成 200 HTML；未来健康检查路径须显式保留。
- index.html 使用需重新验证的缓存策略；带内容哈希的资源可长期 immutable；Cookie/密钥相关 API 使用 no-store。
- 不公开源代码目录、配置文件和 sourcemap；只托管构建产物。清理路径并禁止文件系统越界。
- SPA fallback 只发生在浏览器页面分支，不包裹中继流式/音频/WebSocket 输出，避免破坏 Flusher/Hijacker。
- 静态 handler 位于 IPRateLimit 外层，页面资源加载不消耗管理/中继请求预算。

Docker 多阶段按前端构建 → Go 发行构建 → 运行镜像排列；运行镜像保留上游 HTTPS 所需 CA、SQLite 可写目录和运行用户权限。具体 Compose、多实例与健康检查归 P7；不能把当前没有的部署文件当作已交付。

## 十、里程碑与验收

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |

以下用例纳入验收，不能只以“页面能打开”通过：

1. user 直达管理 URL 得到 403，直接调用受限 API 同样被拒；admin 无法修改用户，root 正常操作。
2. 用户 A 退出后用户 B 登录，不闪现 A 的列表、额度、管理员指标或密钥；服务重启后会话失效可恢复登录。
3. 注册成功没有自动登录假象；零余额用户能找到兑换入口；不存在的自助改密功能不显示。
4. 创建 token 弹窗只出现一次全文，关闭后缓存与日志中无明文；复制结果可直接作为 Bearer key 使用。
5. token 显式 0/false、清空限制、恢复继承、永不过期均与后端字段语义一致；无限额仍受账户余额约束。
6. 渠道测试返回 `success:true, data.ok:false` 时明确显示失败；编辑其他字段不把掩码 key 写入数据库。
7. 流水请求正确携带 p/page_size/model；刷新、返回、越界页和空页处理一致；无全量接口时不冒充全局搜索。
8. 余额 100、计价 130 的结算显示实扣 100、未收 30；小额 quota 不显示成零；超出安全整数不能继续保存。
9. 余额编辑遇到并发消费返回 409 并要求重确认；兑换/批量建码超时不会被自动重试。
10. options 的 JSON 字符串、标量、表达式和空 webhook 均正确序列化；默认倍率合并后重新加载显示实际值。
11. 日趋势按 UTC；管理员全站视图显式 user_id=0；没有指标样本时显示暂无数据；后台轮询失败不清零旧值。
12. 审计展示真实操作者；状态码与失败写操作如实呈现；没有的前后差异不自行补造。
13. 双主题/双语言、长文本、三档视口、200% 缩放、键盘及图表文字摘要通过。
14. 带前端二进制的登录页、深链接、静态资源、缺失资源、未知 API、错误 HTTP 方法逐项通过；后端中继回归不受影响。
15. CI 同时运行默认 Go 检查、前端 lint/typecheck/unit/build、带 frontend 标签的 Go 检查及关键 Playwright 流程，失败阻止发行。

本文的“当前事实”以标注提交及实际 Go 代码为准，P4/P5 等需求文档不视为已实现能力清单。实现新增字段/接口时，同步更新本表、前端类型及契约测试。

## 十二、实现交付索引

- `web/src/`：九个业务页面、登录注册、403/404、Cookie 会话、权限导航、主题/语言与查询状态；通用资源表格使用语义化 HTML，实现本地或服务端分页，不额外引入表格状态库。
- `middleware/management.go`、`middleware/auth.go`、`middleware/audit.go`：同源保护、安全 Cookie 配置、权限接线和审计身份。
- `model/quota_update.go` 与相关 controller：原子余额条件更新、空值/零值/false 语义；`e2e_p6_test.go` 验证实际 API 契约。
- `web/handler.go`、`assets_embed.go`、`assets_stub.go`：浏览器/API 路由隔离和构建标签；`handler_test.go` 验证边界、缓存和 HEAD。
- `web/tests/unit`、`web/tests/e2e`：金额、权限、请求隔离、序列化单测及真实浏览器流程；`e2e_p6_browser_test.go` 提供临时数据库与本地上游。
- `scripts/build-release.mjs`、`Dockerfile`、`.github/workflows/verify.yml`、README：发行脚本、容器构建、持续验证与操作说明。没有执行生产部署。

验收命令及环境以 README 为准。当前采用 Node 24、Vite 7、Vue 3、Tailwind 4，具体安装版本锁定在 `web/package-lock.json`。图表独立异步加载，登录初始资源不加载 ECharts；静态产物不包含 sourcemap。
