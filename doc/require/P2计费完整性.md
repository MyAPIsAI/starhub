# P2 计费完整性：让中转「不亏钱」

P0 只有"事后扣费"，完整版需要三段式资金安全模型（参考 `service/quota.go`、`service/text_quota.go`）。

## 2.1 预扣 → 结算 → 退款

```
请求前: PreConsumeBilling  按 max_tokens 估算预扣 (relay.go:227)
响应后: PostTextConsumeQuota  按 usage 真实值结算差额 (text_quota.go:397)
失败时: Billing.Refund       全额退还预扣
```

- 预扣解决**并发透支**：用户余额 1 元同时发 10 个请求，不预扣会全部放行
- 结算用真实 usage（含 cache token、audio token 细分），多退少补

## 2.2 计价引擎

| 层 | 内容 |
|---|---|
| 基础 | 模型倍率（按次）或 token 倍率（按量），`model/pricing.go` |
| 乘数 | 分组倍率 `group_ratio` × 模型倍率 × 特殊乘数（音频/图片分辨率/视频秒数，`types.PriceData.AddOtherRatio`） |
| 进阶 | 表达式计价 `pkg/billingexpr`（阶梯价、动态价），必须先读 `pkg/billingexpr/expr.md` 的设计约束 |
| 安全 | 所有 float→int 换算走 `common/quota_math.go`（饱和截断，防溢出变成负数=送钱）；乘数上界校验（`dto.MaxImageN` 等）在**请求验证阶段**拒绝 |

## 2.3 Token 精确计量

- 请求侧：tokenizer 估算 prompt tokens（决定预扣额度）
- 响应侧：非流式直接读 `usage`；**流式**必须注入 `stream_options.include_usage`（`relay/compatible_handler.go:47-63`，上游不支持时本地累计 SSE chunk 估算）
- 敏感操作（改余额、改渠道）走 `lockForUpdate` 行锁防并发双花

## P2 交付物

账目对得上、并发不透支、流式不漏计、异常有审计（`quota_saturation` 标记进日志）。
